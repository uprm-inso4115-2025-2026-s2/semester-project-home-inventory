== Domain Attributes Classification for Core Inventory

This section applies the Domain Attributes lecture topic to the Core Inventory subsystem, classifying key domain entities and behaviors by their attributes (Static, Dynamic, Dynamic Inert, Dynamic Active, Discrete).

=== 1. Item Type

An item definition (e.g., "Clorox Bleach 64oz Original").

Classification: *Static, *Discrete

An item type's definition (name, barcode, brand, size) does not change once created, so it is Static; each item type is its own distinct entity, so it is Discrete.

=== 2. Item Instance (Package)

A specific purchase or concrete unit of an item type (purchase date, storage location, expiration date if applicable).

Classification: *Dynamic Inert, *Discrete

An item instance changes only through external actions (member updates, consumption, location change), making it Dynamic Inert; each instance has a separate record, making it Discrete.

=== 3. Household

A living unit grouping locations and inventory items.

Classification: *Static, *Discrete

A household is a structural container that does not change state over time (Static), and each household is unique (Discrete).

=== 4. Location

A storage place within a household (e.g., kitchen cabinet, pantry, fridge, bathroom closet).

Classification: *Static, *Discrete

Locations are structural subdivisions that do not change autonomously (Static) and are uniquely represented (Discrete).

=== 5. Household Member

A person who belongs to a household and participates in consuming, replenishing, or coordinating around items.

Classification: *Static, *Discrete

A member's identity remains stable over time even as item associations change (Static), and each member is a distinct entity (Discrete).

=== 6. Duplicate Detection Logic

System logic that determines whether a new entry is a duplicate at the item-type or item-instance level.

Classification: *Dynamic Active

Duplicate detection executes rule-based behavior when members add or scan items, responding to system events and applying programmed conditions, so it is Dynamic Active (it changes via internally programmed rules and conditions).
