= Core Inventory Form Validation Rules
:showtitle: true
:icons: font

== Overview

This document defines the explicit validation rules implemented in the Core Inventory feature's form validation logic (`form_validators.dart`). These rules make implicit domain concepts explicit and ensure consistent data entry across the application.

== Form Validation Rules

=== Item Name Validation

[cols="1,4", options="header"]
|===
| Rule | Description

| Required
| Item name must not be empty.

| Minimum Length
| Item name must be at least 2 characters.

| Maximum Length
| Item name must be less than 100 characters.

| Domain Rationale
| Names shorter than 2 characters are likely typos or placeholders. Names longer than 100 characters exceed typical product name lengths and may indicate data entry errors.
|===

=== Quantity Validation

[cols="1,4", options="header"]
|===
| Rule | Description

| Required
| Quantity must be provided.

| Numeric
| Quantity must be a valid integer number.

| Non-Negative
| Quantity cannot be negative.

| Maximum
| Quantity cannot exceed 999,999 units.

| Domain Rationale
| Zero quantity is allowed to represent out-of-stock items (Status.EMPTY). Negative quantities would indicate inventory reduction below zero, which is physically impossible. The upper limit prevents accidental absurd entries.
|===

=== Expiration Date Validation

[cols="1,4", options="header"]
|===
| Rule | Description

| Optional
| Expiration date is not required.

| Format
| Must follow YYYY-MM-DD format.

| Future Date
| Expiration date cannot be in the past (excluding current date).

| Domain Rationale
| Expiration dates are optional because not all items expire. Past dates are rejected because they would already be expired upon entry, which should be handled through the expiration alert system instead.
|===

=== Brand/Details Validation

[cols="1,4", options="header"]
|===
| Rule | Description

| Optional
| Brand field is not required.

| Maximum Length
| Brand name must be less than 200 characters.

| Domain Rationale
| Brand information helps distinguish between similar item types (e.g., "Clorox Bleach" vs "Great Value Bleach") but is not required for basic item tracking.
|===

== Error Message Mapping

The following table maps validation failures to user-facing messages:

[cols="1,3", options="header"]
|===
| Validation Failure | User Message

| Empty name
| "Please enter an item name"

| Name too short
| "Name must be at least 2 characters"

| Name too long
| "Name must be less than 100 characters"

| Empty quantity
| "Please enter a quantity"

| Invalid number
| "Please enter a valid number"

| Negative quantity
| "Quantity cannot be negative"

| Quantity too large
| "Quantity is too large"

| Invalid date format
| "Use format: YYYY-MM-DD"

| Past expiration date
| "Expiration date cannot be in the past"

| Empty brand (if required by context)
| "Please enter a brand or product name"

| Brand too long
| "Brand name is too long"
|===

== Implementation Location

These validation rules are implemented in:

- `src/lib/features/core_inventory/presentation/utils/form_validators.dart` — Core validation functions
- `src/lib/features/core_inventory/presentation/widgets/item_form.dart` — UI integration with real-time error display

== Traceability

These validation rules support the following derived goals and requirements:

- *DG-REQ-01*: Create an item record with minimal required information
- *DG-REQ-04*: Routine item updates remain lightweight
- *IR-01*: Item initialization with name and quantity/availability
- *IR-11*: Fast manual entry after barcode failure
