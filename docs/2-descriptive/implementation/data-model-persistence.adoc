== Data Model and Persistence Layer (Milestone 3)

This document defines the data model and persistence layer for the Digital Home Inventory system as implemented in Milestone 3. The system uses **Supabase PostgreSQL** as the primary database with **Row Level Security (RLS)** for access control and **Supabase Realtime** for live synchronization.

This documentation reflects the actual Dart model implementations. For auto-generation and verification, refer to the <<regeneration_script, regeneration script>>.

---

== Core Entities

=== Household

Represents a shared living unit where members manage household essentials.

[cols="1,2,3", options="header"]
|===
| Attribute | Type | Description
| id | INT (PK) | Unique household identifier (auto-increment)
| name | TEXT | Household name/label
| owner_id | INT (FK → households.owner_id) | User who owns the household
|===

**Cardinality:** One Household has many Members, many Inventories, many Expenses.

**Source:** `src/lib/features/sharing_budget/data/models/household_model.dart`

---

=== Household Member

Links a user to a household with a specific role (owner, member, viewer).

[cols="1,2,3", options="header"]
|===
| Attribute | Type | Description
| id | INT (PK) | Unique member record identifier
| household_id | INT (PK/FK → households.id) | Reference to household
| user_id | INT (PK/FK) | Reference to authenticated user
| role | ENUM | owner, member, or viewer (MemberRole enum)
|===

**Cardinality:** Many-to-many between User and Household.

**Source:** `src/lib/features/sharing_budget/data/models/household_member_model.dart`

---

=== Product

Defines a product type (independent of inventory instances). Products are shared catalog items with metadata.

[cols="1,2,3", options="header"]
|===
| Attribute | Type | Description
| id | INT (PK) | Unique product identifier
| name | TEXT | Product name (e.g., "Milk")
| description | TEXT | Product description
| tags | TEXT[] | Optional tags (Tag enum values: BEVERAGES, SNACKS, DAIRY, PROTEINS, VEGETABLES, etc.)
| unit | TEXT | Unit of measure (ct, lb, oz, L, etc.) — optional
| imageUrl | TEXT | Optional URL to product image
|===

**Cardinality:** One Product has many Stock Entries.

**Source:** `src/lib/features/core_inventory/data/models/product.dart`

---

=== Inventory

Represents a container (room, household) that holds stock of products.

[cols="1,2,3", options="header"]
|===
| Attribute | Type | Description
| id | INT (PK) | Unique inventory identifier
| owner_id | INT | Owner ID (room, household, or user identifier)
| stock | JSONB | Map of product_id → List<Stock> (stores stock instances)
|===

**Cardinality:** One Inventory holds stock entries for many Products.

**Source:** `src/lib/features/core_inventory/data/models/inventory.dart`

---

=== Stock

Represents a single instance (package/unit) of a product in an inventory.

[cols="1,2,3", options="header"]
|===
| Attribute | Type | Description
| id | INT (PK) | Unique stock entry identifier
| brand | TEXT | Brand/manufacturer of the stock
| quantity | INT | Current quantity (must be > 0)
| status | ENUM | Status.EMPTY, Status.LOW, Status.NORMAL, Status.FULL, Status.EXPIRED
| owner_id | INT | Optional owner ID for personal vs. shared visibility
| expiration_date | TIMESTAMPTZ | Optional expiration date
|===

**Cardinality:** Many Stock Entries belong to one Inventory and one Product.

**Source:** `src/lib/features/core_inventory/data/models/stock.dart`

---

=== Expense

Records financial transactions for households (shared spending tracking).

[cols="1,2,3", options="header"]
|===
| Attribute | Type | Description
| id | INT (PK) | Unique expense identifier
| household_id | INT (FK → households.id) | Associated household
| user_id | INT | User who logged the spending (optional)
| amount | DECIMAL(10,2) | Monetary value
| category | TEXT | Spending category (optional)
| description | TEXT | Optional notes/description
| incurred_on | TIMESTAMPTZ | When transaction occurred
| created_at | TIMESTAMPTZ | Record creation timestamp
|===

**Cardinality:** Many Expenses belong to one Household. Many Expenses belong to one User.

**Source:** `src/lib/features/sharing_budget/data/models/expense_model.dart`

== Persistence Layer

=== Primary Database: Supabase PostgreSQL

- Hosted PostgreSQL database managed through Supabase
- All core entities stored as tables with integer primary keys
- Row Level Security (RLS) enforced for all tables (planned)
- Real-time enabled for households and inventory tables (planned)

=== Table Schema

==== households
[source,sql]
----
CREATE TABLE households (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  owner_id INT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
----

==== household_members
[source,sql]
----
CREATE TABLE household_members (
  id SERIAL PRIMARY KEY,
  household_id INT NOT NULL REFERENCES households(id),
  user_id INT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('owner', 'member', 'viewer')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);
----

==== products
[source,sql]
----
CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT NOT NULL,
  tags TEXT[] DEFAULT '{}',
  unit TEXT,
  imageUrl TEXT
);
----

==== inventories
[source,sql]
----
CREATE TABLE inventories (
  id SERIAL PRIMARY KEY,
  owner_id INT NOT NULL,
  stock JSONB DEFAULT '{}'
);
----

==== expenses
[source,sql]
----
CREATE TABLE expenses (
  id SERIAL PRIMARY KEY,
  household_id INT NOT NULL REFERENCES households(id),
  user_id INT,
  amount DECIMAL(10, 2) NOT NULL,
  category TEXT,
  description TEXT,
  incurred_on TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
----

=== Authentication: Supabase Auth

- Users authenticated via Supabase Auth (JWT-based)
- RLS policies use authenticated user ID for access control
- Session management handled by Supabase Flutter SDK

=== File Storage: Supabase Storage

- Product images stored in storage buckets (future implementation)
- Signed URLs for private assets

=== Local Persistence (Flutter Client)

- SharedPreferences for user preferences and settings
- In-memory state management via Cubit/Bloc
- Pending offline changes queued for sync

== Migration Notes (M2 → M3)

The following changes were made between Milestone 2 and Milestone 3 to align the data model with actual implementation:

[cols="1,2,3,4", options="header"]
|===
| Entity | Change Type | Details | Notes
| Household | ID Type | Changed from UUID to INT | All IDs now use auto-increment integers
| HouseholdMember | ID Type | Changed from UUID to INT | Composite PK (id) with FK references
| HouseholdMember | Schema Alignment | Removed created_at if not in M2 | Basic entity with id, household_id, user_id, role
| Product | New Entity | Extracted from InventoryItem concept | ProductModel represents the product catalog entry
| Inventory | Restructured | Now holds stock Map<String, List<Stock>> | Stock is embedded in JSONB, not separate table
| Stock | Renamed/Added | Status enum (EMPTY, LOW, NORMAL, FULL, EXPIRED) | New field: brand, status; removed threshold
| Expense | Schema | Uses incurred_on not purchase_date or expense_date | Simplified: id, household_id, user_id, amount, category, description, incurred_on, created_at
| Expense | Removed Fields | No transaction_type, merchant_name, paid_by_user_id, item_id | M3 expense is simpler; detailed expense tracking deferred
| Notification | Planned | No Dart model yet | SQL schema designed but not implemented
| SweepRun | Planned | No Dart model yet | Audit logging designed but not implemented
|===

**Backward Compatibility:**

- If migrating from M2: **Create new tables** (integer-based schema) and run data transformation scripts
- Soft deletion not yet implemented; deletes are hard (can be added in M4)
- Stock status is derived from quantity and expiration logic; not auto-migrated

== Key Implementation Notes

=== Stock Status Enum

The `Status` enum in `StockModel` is used to track inventory state:

- `EMPTY`: Quantity is zero
- `LOW`: Quantity below household threshold
- `NORMAL`: Quantity in acceptable range
- `FULL`: Quantity at or above max capacity
- `EXPIRED`: Expiration date has passed

=== Inventory as JSONB

The `stock` field in `InventoryModel` is a `Map<String, List<StockModel>>` stored as JSONB in Postgres. Key is product ID (as string); value is list of stock instances. This design allows:

- Flexible handling of multiple brands/batches per product
- Efficient nested filtering in Supabase
- Atomic updates via Postgres JSONB operators

=== Product vs. Stock

- **Product:** Shared catalog item (name, description, tags, unit, image)
- **Stock:** Individual instance in an inventory (brand, quantity, status, expiration)

A household may have multiple Stock entries for the same Product (different brands, batches).
