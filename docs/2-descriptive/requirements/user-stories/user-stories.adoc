== User Stories

These user stories describe the core user-visible behaviors of the Digital Home Inventory system for Milestone 1. Each is written from a persona's perspective and supported by measurable acceptance criteria. Identifier prefixes: US-INV (Core Inventory), US-ALT (Alerts & Restock), US-SB (Sharing & Budget), US-RPT (Reports & Insights).

=== US-INV-01: Add items to inventory

As *Mateo* (busy solo student), I want to *quickly add items to my tracked inventory after shopping*, so that *I can reliably know what I have without relying on memory*.

*Also affects:* Sofia, Julian, Andrea
*Priority:* High

**Acceptance Criteria**
* A prominent "Add Item" entry point is available from the inventory view.
* Adding an item requires only minimal fields (name + quantity/availability), with optional fields (category, location, ownership status, expiration date).
* Creating an item is low-effort (goal: under 1 minute for a small set of items, assuming typical mobile input).
* After saving, the item appears in the inventory list without a manual refresh.
* The user can edit an item from the list (e.g., correct name/variant), and updates are reflected consistently wherever they appear.

[NOTE]
====
Expiration dates are optional. If unknown or unreadable, the system treats expiration status as unknown and avoids false "expired" alerts.
====

=== US-INV-02: See what belongs to whom

As *Sofia* (budget-conscious roommate), I want to *see which items are shared and which belong to specific people*, so that *I can avoid conflict and protect my personal purchases*.

*Also affects:* Julian, Andrea
*Priority:* High

**Acceptance Criteria**
* Every item in a shared household includes an ownership indicator: personal (linked to a member) or shared.
* The item detail view shows ownership status and relevant metadata (purchase date/cost when recorded).
* When adding/editing an item, the user can set ownership to personal or shared.
* Changing ownership (personal ↔ shared) updates the tracked record and becomes visible to members after synchronization.
* Spending views (if enabled) separate personal from shared spending so users understand personal vs household costs.

=== US-ALT-01: Receive low-stock warnings

As *Julian* (diet-constrained student), I want to *receive low-stock warnings for items I rely on*, so that *I can reorder in time and avoid unexpected shortages*.

*Also affects:* Mateo, Andrea
*Priority:* High

**Acceptance Criteria**
* The user can set a low-stock threshold per item (with sensible defaults if none is set).
* When tracked quantity crosses from NORMAL/IN_STOCK to LOW_STOCK (threshold boundary), the item is flagged low-stock.
* Low-stock alerts are generated primarily on state transitions (e.g., NORMAL → LOW_STOCK) and deduplicated (re-running checks without state change does not spam alerts).
* When multiple items are low, notifications may be grouped or summarized to avoid overwhelming users.
* Low-stock status remains consistent across views (inventory list, restock list/planner, dashboard summaries).

=== US-SB-01: Split shared purchases with roommates

As *Andrea* (unofficial household manager), I want to *record shared purchases and split costs with roommates*, so that *reimbursements are clear and disputes are reduced*.

*Also affects:* Sofia, Mateo, Julian
*Priority:* High

**Acceptance Criteria**
* The user can record a purchase with total cost and date, marking line items (or the purchase) as shared vs personal.
* The system can compute a split for shared items among selected members (default equal split; adjustable).
* Members can view the breakdown of a shared purchase (what was bought, how the split was calculated).
* Payments can be marked paid/unpaid, with a simple reimbursement status view.
* Disputes can be flagged on a purchase line item (recording that discussion is needed) without deleting transaction history.

=== US-RPT-01: See household dashboard with insights

As *Andrea* (unofficial household manager), I want to *open one screen and quickly see what needs attention*, so that *I can plan restocking without guessing or repeatedly messaging roommates*.

*Also affects:* Sofia, Mateo, Julian
*Priority:* Medium

**Acceptance Criteria**
* The dashboard summarizes: number of low-stock items, number of expiring/expired items (when expiration dates exist), and current-period spending (if enabled).
* The user can filter the dashboard by location (e.g., kitchen/bathroom) and return to the unfiltered view.
* Summary counts update after changes are recorded and synchronized (no stale information).
* Low/expiring summaries include location context when available (e.g., "toilet paper low in bathroom").
* The dashboard surfaces the household's top-level status without navigating multiple screens.
