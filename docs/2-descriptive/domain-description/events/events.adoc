== Events

Domain events represent instantaneous state changes in the domain that matter to stakeholders. Each event is phrased in the past tense to emphasize that a state change has just occurred. Events are independent of any particular system-to-be, even if a later system represents or reacts to them.

[NOTE]
====
#The full list of domain events — together with their definitions and notes — is maintained as part of <<_terminology>> under the rows tagged *Event* or *State / Event*. There is no separate event definition table here, in order to avoid divergence between the two lists.#

#If a domain event is added, renamed, or refined, the change must be made directly in <<_terminology>>. This section only describes how events are used; it does not redefine their names.#

#Worked-out event sequences for standard domain scenarios appear in <<_terminology_walkthroughs>>; see that section for the cases where two events were found to describe the same transition (e.g., *Item approaching expiration* and *Near-expiry*) and the recommended consolidations.#

=== #Event categories#

#The events in <<_terminology>> fall into the following categories, useful when reasoning about the domain:#

* #*Inventory lifecycle events:* item instance acquired, stored, consumed, replenished, discarded; backup opened.#
* #*Availability and expiration events:* low-stock judged, out-of-stock reached, item approaching expiration, item expired.#
* #*Coordination events:* duplicate purchase, replenishment decided, restock entry created / updated, household membership changed.#
* #*Alert and notification events:* alert generated, alert dismissed / deferred.#
* #*Spending and budget events:* spending recorded, budget threshold crossing, budget cycle started / ended.#

#Use these categories only as a navigation aid; the authoritative names and definitions are the rows in <<_terminology>>.#
