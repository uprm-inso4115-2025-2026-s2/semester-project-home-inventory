== Functions

Major domain functions/capabilities, described independently of UI. Each includes a signature naming its inputs and outputs so the effect of the operation can be stated precisely.

[NOTE]
====
The action names used here (e.g., *Consumption*, *Replenishment*, *Low-stock judgment*, *Transaction (quantity change)*) are defined in <<_terminology>>. This section is operational: it adds formal signatures and pre-/post-conditions on top of those terms, not new definitions. If a function introduces a new action name, that name must also be added to the terminology table.
====

=== Stock item instance

Introduce new item instances of an item type into a household location, whether as first stocking or replenishment. Afterward, checking the location shows the added quantity.

 stockItem : Household × ItemType × Location × QuantityDelta × ExpirationDate? → Household

* _Location_ determines where the new instances are placed; _QuantityDelta_ is the number of units added.
* _ExpirationDate_ is optional; if provided, it is associated with the new instances.
* The returned Household reflects the updated inventory.

=== Create item instance

Create a new tracked item instance associated with an item type and an initial inventory state.

----
createItemInstance : Household × ItemType × Quantity × Location → ItemInstance
----

Example:

----
createItemInstance(myHome, Rice, 1, pantryShelf) -> riceBag01
----

* Returns a newly created `ItemInstance` associated with the specified household inventory.
* The created item instance records its initial quantity and storage location.
* The returned instance may later be consumed, moved, shared, expired, or removed through other inventory operations.
* If the inventory model supports cumulative quantity tracking instead of uniquely identifiable physical items, the created instance may represent a tracked quantity group rather than a single physical object.

=== Check location

Inspect a location to determine which item types it contains and the quantities currently stored there (an observation function).

----
checkLocation : Household × Location → (ItemType → Amount)
----

Example:

----
checkLocation(myHome, laundryBelowSink)[CatLitter] -> 2
----

* Returns a quantity-aware mapping of item types stored at the specified location.
* Supports expressing pre-/post-conditions for inventory operations — e.g., after `stockItem` adds 3 units of rice to the kitchen cabinet, `checkLocation(myHome, kitchenCabinet)[Rice]` increases by 3.
* Models inventory state as tracked quantities rather than simple item presence or absence.

=== Move item instance

Change where an item instance is stored within the household inventory. The system first determines the item instance’s current location before applying the move operation. After moving, the previous location no longer includes the item instance and the destination location reflects the updated inventory state.

----
moveItemInstance : Household × ItemInstance × Location → Household
----

Example:

----
moveItemInstance(myHome, riceBag01, pantryShelf)
----

* _Location_ represents the destination location.
* The operation determines the current location of the item instance before updating inventory state.
* Ownership, expiration information, and item-type identity are preserved during the move operation.
* If the inventory model tracks cumulative quantities instead of uniquely identifiable instances, the operation updates quantity counts at both the source and destination locations.

=== Record consumption

Decrease tracked availability when a household member uses part or all of an item. Consumption may be modeled at two levels depending on how the item is represented: as a uniquely tracked item instance or as a cumulative quantity of an item type.

----
consumeInstance : Household × ItemInstance → Household
consumeAmount : Household × ItemType × QuantityDelta → Household
----

Examples:

----
consumeInstance(myHome, soupCan01)
consumeAmount(myHome, Rice, 2)
----

* `consumeInstance` applies when the household tracks a specific physical unit, such as a particular can, carton, or package. The consumed instance is marked unavailable, consumed, or removed from active inventory.
* `consumeAmount` applies when the household tracks inventory cumulatively, such as "2 cups of rice" or "3 rolls of paper towels." The operation decreases the tracked amount for the item type.
* `QuantityDelta` is used only for cumulative quantity updates and must not reduce the tracked amount below zero.
* This separates unique item tracking from bulk quantity tracking: individual tracking happens at the `ItemInstance` level, while bulk consumption and count updates happen at the `ItemType` / amount level.

=== Judge low-stock

Determine whether an item type is low based on household strategy or threshold.

 isLowStock : ItemType × Availability × Threshold? → Bool

* If a _Threshold_ is provided and _Availability_ is at or below it, returns true; otherwise the function may rely on qualitative strategies.

=== Determine expiration status

Classify an item instance's expiration state when an expiration date exists.

 expirationStatus : ItemInstance × DateNow → (Active | NearExpiry | Expired | Unknown)

* Returns _Unknown_ when there is no expiration date or it is unreadable; _NearExpiry_ applies within the near-expiry window.

=== Create restock entry

Add an item type to the restock list/planner with a reason.

 addToRestockList : RestockList × ItemType × Reason → RestockList

* _Reason_ is one of LOW_STOCK, OUT_OF_STOCK, EXPIRED.

=== Defer / dismiss restock entry

Allow a household member to postpone or remove an entry from restock planning.

 deferRestock : RestockList × ItemType × Until? → RestockList

* _Until_ is an optional date/time for when the entry should reappear.

=== Generate alert

Create an alert record when an actionable state is reached.

 generateAlert : AlertLog × AlertType × Target → AlertLog

* _AlertType_ is one of LOW_STOCK, OUT_OF_STOCK, NEAR_EXPIRY, EXPIRED, BUDGET_THRESHOLD.
* _Target_ is the item type, item instance, or budget that triggered the condition.

=== Acknowledge alert

Record a household member's decision to dismiss or defer an alert.

 ackAlert : AlertLog × Alert × Action(dismiss|defer) × Until? → AlertLog

=== Record quantity change transaction

Append a transaction describing why and when availability changed.

 recordTransaction : TransactionLog × ItemInstance × Change × Reason × Time → TransactionLog

=== Record spending event

Create a spending entry capturing who paid, how much, when, and whether it is shared or personal.

 recordSpending : Household × Amount × Date × Payer × Scope × ItemType? × Category? → Household

* _Payer_ is the member who purchased; attribution is retained even after inventory corrections.
* _Scope_ determines whether spending is shared or personal.

=== Adjust spending entry

Correct spending records via adjustment/refund entries rather than destructive edits.

 adjustSpending : Household × SpendingEntry × Adjustment → Household

=== Compute budget status

Compute spent-to-date and remaining budget for a household or category within a cycle.

 budgetStatus : Budget × List SpendingEntry × DateNow → BudgetStatus
