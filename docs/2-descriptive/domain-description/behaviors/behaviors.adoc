== Behaviors

Recurring behaviors or rules in the domain: patterns, policies, and "how things are done."

=== Behavior patterns

* *Restock cycle:* A member consumes an item instance -> availability decreases -> low-stock is judged or a threshold is crossed -> a replenishment decision is made -> more of the item type is acquired.
* *Shared purchase flow:* A member buys a shared item -> the purchase is recorded -> the household understands the cost belongs to the shared context, not only one person.
* *Expiration monitoring:* An item instance approaches expiration -> the household notices or is informed -> the item is used, discarded, or left in place depending on practice.

=== Domain rules

* One barcode corresponds to exactly one *Item type* definition.
* A duplicate *Item instance* entry submitted within a short window may be treated as an addition to an existing tracked record rather than a separate new record, unless members explicitly keep them separate.
* *Spending entries* are historical records; inventory corrections should not silently overwrite financial history.
* A *Household* has one administrative responsibility at a time when that role is formally represented.
* If that responsibility is transferred, the new one must be established before the previous admin leaves.

=== Edge cases

* If an item instance has no expiration date, expiration-based behavior cannot be derived from date information alone.
* If a household admin leaves without transferring responsibility, shared-household administration becomes unresolved until another member takes over.

=== Shared-Household Invitation and Membership Changes

In shared households, participation changes over time as members are invited, leave, or have access revoked. A household invitation is a temporary request to join a household context whose state (sent, accepted, declined, expired, or revoked) determines who participates in coordination and who should continue to receive shared information. The full lifecycle rules, permissions, and delivery mechanism are specified in the requirements section (Shared-Household Invitations and Access Changes).
